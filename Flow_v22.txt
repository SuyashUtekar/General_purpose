    <div class="step-header">
      <span class="step-title">User Query — Entry Point</span>
      <span class="badge b-node">START NODE</span>
      <span class="badge b-fast">0ms</span>
    </div>
    <p class="step-desc">Raw natural language query from an RBI officer enters the system. Session is initialized with dept, session_id, and cleared short-term memory.</p>
    <ul class="points">
      <li><strong>Receive query</strong> as plain string from the FastAPI <code>/query</code> endpoint or chat UI</li>
      <li><strong>Initialize state</strong> — write <code>query</code>, <code>dept</code>, <code>session_id</code> into <code>RBIState</code>. Set <code>audit_log=[]</code>, <code>is_valid=False</code>, all result keys <code>None</code></li>
      <li><strong>Load dept access rules</strong> from Redis — <code>r.get("rbi:access:DEPT_FRAUD")</code> — cached at startup, 0ms</li>
      <li><strong>Clear short-term session memory</strong> — prevents leakage from prior session</li>
    </ul>
    <div class="imp">No LLM call here — pure state initialization. Fastest possible entry.</div>
  </div>
</div>

<!-- STEP 2 -->
<div class="step">
  <div class="step-num-col">
    <div class="step-num" style="color:var(--blue);border-color:var(--blue)">02</div>
    <div class="step-line"></div>
  </div>
  <div class="step-body">
    <div class="step-header">
      <span class="step-title">Decompose & Paraphrase Node</span>
      <span class="badge b-node">NODE · PARALLEL</span>
      <span class="badge b-med">200ms</span>
    </div>
    <p class="step-desc">Runs SpaCy NLP decomposition and SLM paraphrasing simultaneously using asyncio.gather(). SpaCy model is loaded once at startup — never reloaded per query.</p>
    <div class="io-row">
      <div class="io-box">
        <div class="io-lbl in">Reads from State</div>
        <div class="io-key">query <span class="io-val">— raw user input</span></div>
        <div class="io-key">dept <span class="io-val">— for domain context</span></div>
      </div>
      <div class="io-box">
        <div class="io-lbl out">Writes to State</div>
        <div class="io-key">decomposition <span class="io-val">— entities + filters</span></div>
        <div class="io-key">paraphrases <span class="io-val">— [formal, keyword]</span></div>
      </div>
    </div>
    <div class="par-grid">
      <div class="par-box">
        <div class="par-title" style="color:var(--blue)">SpaCy NLP Decomposition</div>
        <ul>
          <li>Load singleton model — never reload per query</li>
          <li>NER: extract bank names, amounts, DPD, dates, cities, circular numbers</li>
          <li>Dependency parse: subject + predicate + object</li>
          <li>Split multi-intent queries into sub-queries list</li>
          <li>Output: entities{}, filters[], sub_queries[], join_hints[]</li>
        </ul>
      </div>
      <div class="par-box">
        <div class="par-title" style="color:var(--teal)">SLM Paraphrasing (flan-t5-small)</div>
        <ul>
          <li>Quantized INT8 model — 80ms vs 600ms for large model</li>
          <li>Para 1: formal RBI language — for dense vector search</li>
          <li>Para 2: keyword-dense — for BM25 pre-filter</li>
          <li>Example: "show bad loans PNB" → "List NPA accounts at Punjab National Bank" + "NPA DPD overdue PNB loans"</li>
          <li>All 3 versions used in vector retrieval for higher recall</li>
        </ul>
      </div>
    </div>
    <div class="imp">asyncio.gather() — both run simultaneously: total = 200ms not 400ms</div>
  </div>
</div>

<!-- STEP 3 -->
<div class="step">
  <div class="step-num-col">
    <div class="step-num" style="color:var(--amber);border-color:var(--amber)">03</div>
    <div class="step-line"></div>
  </div>
  <div class="step-body">
    <div class="step-header">
      <span class="step-title">Hierarchical Intent Classifier Node</span>
      <span class="badge b-agent">AGENT NODE</span>
      <span class="badge b-fast">5–150ms</span>
    </div>
    <p class="step-desc">Two-level classification in one node. L1 validates (Valid/Invalid). L2 classifies source and query type. Rule-first with LLM fallback — skips LLM for 80% of queries.</p>
    <div class="io-row">
      <div class="io-box">
        <div class="io-lbl in">Reads from State</div>
        <div class="io-key">query, decomposition, paraphrases</div>
      </div>
      <div class="io-box">
        <div class="io-lbl out">Writes to State</div>
        <div class="io-key">is_valid <span class="io-val">True / False</span></div>
        <div class="io-key">sources <span class="io-val">["sql","nosql","vector"]</span></div>
        <div class="io-key">query_type <span class="io-val">report/lookup/viz/multi_hop</span></div>
        <div class="io-key">invalid_reason <span class="io-val">string or None</span></div>
      </div>
    </div>
    <ul class="points">
      <li><strong>L1 Layer 1 — Regex (0ms):</strong> Block <code>DROP|DELETE|UPDATE|INSERT|TRUNCATE</code>, XSS patterns, credential keywords. Return <code>is_valid=False</code> immediately on match</li>
      <li><strong>L1 Layer 2 — Structural check (2ms):</strong> Length 5–1000 chars, English/Hindi only, no excessive special chars</li>
      <li><strong>L1 Layer 3 — Domain keywords (5ms):</strong> Scan for <code>bank, npa, fraud, dpd, penalty, circular, kyc, upi, camels, sarfaesi</code>. Found → <code>is_valid=True</code>, skip LLM</li>
      <li><strong>L1 Layer 4 — LLM fallback (150ms, only if layers 1-3 inconclusive):</strong> Yes/No prompt to lightweight LLM</li>
      <li><strong>L2 — Routing cache check (0ms):</strong> Fingerprint query → check Redis routing cache. Hit → return source + query_type instantly</li>
      <li><strong>L2 — Signal rule matching (5ms):</strong> count/sum/filter → SQL | complaint/alert → NoSQL | circular says → Vector | multiple entity types → multi_hop</li>
      <li><strong>L2 — Single combined LLM call (150ms, only if rules inconclusive):</strong> One structured output returns sources[], query_type, confidence together</li>
      <li><strong>Store routing result</strong> in Redis cache with 300s TTL</li>
    </ul>
    <div class="imp">Combined L1+L2 in one node. Rule-first skips LLM 80% of time — saves 150ms per query</div>
  </div>
</div>

    <div class="step-num" style="color:var(--violet);border-color:var(--violet)">04</div>

      <span class="badge b-agent">AGENT NODE</span>
      <span class="badge b-fast">0–200ms</span>
    </div>
    <p class="step-desc">Builds the execution DAG for the executor. Checks plan cache first — known patterns return instantly with 0ms planning. Novel queries trigger LLM planning.</p>
    <div class="io-row">
      <div class="io-box">
        <div class="io-lbl in">Reads from State</div>

      </div>
    </div>
    <ul class="points">
      <li><strong>Plan cache lookup (0ms):</strong> Key = <code>query_type + sorted(sources)</code>. Redis hit → return plan instantly, skip LLM entirely. Known: sql_report→[nl_sql,validator,viz,synth] | vector_lookup→[vector,synth] | multi_hop→[parallel,join,validator,viz,synth]</li>
      <li><strong>LLM planning (200ms, novel patterns only):</strong> Inject L2 output + tool docstrings + dept access rules. LLM outputs DAG with parallel execution flags</li>
      <li><strong>Context assembly:</strong> Load short-term session memory (last 3 turns). Load long-term memory — domain glossary, applicable RBI norms. Apply token budget per tool</li>
      <li><strong>Dept access enforcement:</strong> Load <code>allowed_sources</code> and <code>denied_fields</code> for current dept. Attach to plan — each tool enforces independently</li>
      <li><strong>Store new plan</strong> in Redis plan cache with 600s TTL</li>
    </ul>
    <div class="imp">Plan cache hit = 0ms. New patterns = 200ms. Either way executor gets a ready DAG.</div>

<!-- STEP 6 - NL-SQL -->
<div class="step">
  <div class="step-num-col">
    <div class="step-num" style="color:var(--green);border-color:var(--green)">05</div>
    <div class="step-line"></div>
  </div>
  <div class="step-body">
    <div class="step-header">
      <span class="step-title">NL-SQL Tool</span>
      <span class="badge b-tool">TOOL NODE</span>
      <span class="badge b-med">250ms</span>
    </div>
    <p class="step-desc">Generates and executes parameterized SQL against PostgreSQL via MCP connector. AST guard rails run before any DB execution — bad queries never touch the database.</p>
    <ul class="points">
      <li><strong>Fetch schema from Redis (0ms):</strong> Load relevant table schemas, join map, column stats — only tables needed for this query</li>
      <li><strong>Fetch dept access rules (0ms):</strong> Get <code>allowed_sources</code>, <code>denied_fields</code> for current dept from Redis</li>
      <li><strong>LLM generates SQL (200ms):</strong> Prompt: system rules (SELECT only) + table schemas + join map + few-shot examples + decomposition entities + denied_fields</li>
      <li><strong>AST Guard Rail 1 (2ms):</strong> Parse SQL with <code>sqlparse</code> — block if statement type not SELECT</li>
      <li><strong>AST Guard Rail 2:</strong> Scan all tokens for <code>DROP|DELETE|UPDATE|INSERT|TRUNCATE|ALTER|GRANT|EXEC</code> — reject if found</li>
      <li><strong>AST Guard Rail 3:</strong> Verify all table names against schema metadata — reject hallucinated tables</li>
      <li><strong>AST Guard Rail 4:</strong> Verify all column names exist in respective schemas — reject hallucinated columns</li>
      <li><strong>AST Guard Rail 5:</strong> Auto-inject <code>LIMIT 500</code> if no LIMIT clause present</li>
      <li><strong>AST Guard Rail 6:</strong> Strip denied PII fields from SELECT list per dept access rules</li>
      <li><strong>Execute (50ms):</strong> asyncpg connection pool (min 5, max 20), read-only connection. Tag result with row_count, execution_time_ms, table_names, query_hash</li>
      <li><strong>Write audit entry async</strong> — non-blocking, does not hold up result return</li>
    </ul>
    <div class="imp">AST pre-parse blocks bad SQL in 2ms — never hits the database</div>
  </div>
</div>

<!-- STEP 7 - NL-NoSQL -->
<div class="step">
  <div class="step-num-col">
    <div class="step-num" style="color:var(--green);border-color:var(--green)">06</div>
    <div class="step-line"></div>
  </div>
  <div class="step-body">
    <div class="step-header">
      <span class="step-title">NL-NoSQL Tool</span>
      <span class="badge b-tool">TOOL NODE</span>
      <span class="badge b-med">250ms</span>
    </div>
    <p class="step-desc">Generates and executes MongoDB find() / aggregate() queries via Motor async client. Only READ operations allowed — insert/update/delete/drop blocked at query parse time.</p>
    <ul class="points">
      <li><strong>Fetch collection metadata from Redis (0ms):</strong> Field names, types, index definitions, example values for relevant collection</li>
      <li><strong>LLM generates MongoDB query (200ms):</strong> System prompt restricts to <code>find()</code> and <code>aggregate()</code> only. Inject collection schema + index map + soft FK references</li>
      <li><strong>Guard Rail 1:</strong> Parse JSON query — only <code>find</code> and <code>aggregate</code> allowed. Block <code>insert/update/delete/drop/$out/$merge</code></li>
      <li><strong>Guard Rail 2:</strong> Verify all field names in filter exist in collection schema</li>
      <li><strong>Guard Rail 3:</strong> Auto-add projection to exclude PII fields not accessible to current dept</li>
      <li><strong>Guard Rail 4:</strong> Auto-inject <code>.limit(200)</code> if no limit present</li>
      <li><strong>Execute (50ms):</strong> AsyncIOMotorClient — non-blocking async execution. Serialize BSON to plain dicts</li>
      <li><strong>Write audit entry async</strong></li>
    </ul>

      <span class="step-title">Vector Search Tool</span>
      <span class="badge b-tool">TOOL NODE</span>
      <span class="badge b-fast">30ms</span>
    </div>
    <p class="step-desc">Two-stage retrieval: BM25 keyword pre-filter narrows 1,154 chunks to 50 candidates, then dense embedding search runs on subset only — 10x faster than full index scan.</p>
    <ul class="points">
      <li><strong>Metadata pre-filter (2ms):</strong> Filter index to chunks where <code>dept_relevance</code> includes current dept. Filter by <code>circular_ref</code> if query mentions specific circular number</li>
      <li><strong>BM25 pre-filter on keyword paraphrase (10ms):</strong> Run keyword search using keyword-dense paraphrase. Narrow to top-50 candidate chunks</li>
      <li><strong>Embedding cache check (0ms):</strong> Check Redis embedding cache — hit → return cached vector, skip embedding model (saves 80ms)</li>
      <li><strong>Dense vector search on 50 candidates (20ms):</strong> BAAI/bge-m3 embeddings. Cosine similarity on BM25 subset only — not full 1,154 chunk index</li>
      <li><strong>Hybrid rerank:</strong> Final score = 0.4 × BM25_score + 0.6 × cosine_similarity. Return top-10 chunks</li>
      <li><strong>OCR/Image cache check:</strong> For image or table chunks → check permanent OCR cache. Return cached Markdown/JSON — never re-run OCR</li>
      <li><strong>Write audit entry async</strong></li>
    </ul>
    <div class="imp">Two-stage: 10x smaller search space — 90ms saved vs full index dense scan</div>

    <p class="step-desc">Fires all needed tool coroutines simultaneously. Total time = slowest single tool (~300ms), not sum (~900ms). Used only when sources has 2+ entries.</p>

      <li><strong>Return all results:</strong> Each tool writes to its own state key — sql_result, nosql_result, vector_result independently</li>
